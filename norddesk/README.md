# NordDesk — свой удалённый доступ

Своя система удалённого доступа к ПК в стиле AnyDesk/RuDesktop, но с открытым
кодом и без сторонних сервисов: соединение идёт через **твой** релей на VPS, а
трафик зашифрован сквозным ключом, которого у релея нет.

Написано на чистом Go **без внешних зависимостей** (только стандартная
библиотека + прямые вызовы WinAPI). Собирается в GitHub Actions, как и остальные
части репозитория.

## Из чего состоит

| Компонент | Где работает | Что делает |
|-----------|--------------|------------|
| `cmd/relay` → `norddesk-relay` | Linux (VPS) | Сводит хост и клиента по 9-значному ID и прозрачно переливает байты. Экрана/ввода/файлов **не видит** — всё зашифровано. |
| `cmd/host` → `NordDesk-Host.exe` | Windows (управляемый ПК) | Показывает ID и код, спрашивает согласие, транслирует экран, принимает ввод и файлы на рабочий стол. |
| `cmd/viewer` → `NordDesk.exe` | Windows (твой ПК) | Нативное окно (HTML в Edge, режим приложения, как у `NordKey.exe`): экран на canvas, управление мышью/клавиатурой, перетаскивание файлов. |

Внутренние пакеты: `internal/wire` (формат сообщений), `internal/secure`
(сквозное шифрование), `internal/relaylink` (протокол рандеву), `internal/screen`
(захват экрана GDI), `internal/wininput` (ввод + буфер обмена), `internal/localws`
(минимальный WebSocket для окна клиента).

## Модель безопасности

Доступ даётся так же, как в готовых решениях, но под твоим контролем:

1. Хост показывает **ID** (9 цифр) и **код подключения** (6 цифр, одноразовый на
   каждое подключение; либо постоянный пароль для своих машин — флаг `-pw`).
2. Клиент вводит ID и код. Код — это пароль, который «вплетается» в ключ
   шифрования (X25519 + HKDF). Без верного кода сквозной канал не соберётся.
3. В обычном режиме хост **дополнительно** показывает окно «Разрешить
   управление?» — сессия не начнётся, пока человек за ПК не нажмёт «Да».

Почему релею можно не доверять:

- Ключи вырабатываются напрямую между хостом и клиентом (эфемерный X25519).
  Пассивный релей не знает приватных ключей, поэтому расшифровать не может.
- Данные шифруются **AES-256-GCM**, у каждого направления свой ключ и счётчик
  nonce (защита от повтора).
- Подтверждающие метки (HMAC) ловят активную попытку MITM: подменивший ключи
  релей не пройдёт сверку без кода. Остаётся лишь онлайновый подбор кода — по
  одной попытке на подключение, и хост всё равно требует «Да».

## Сборка

Автоматически в GitHub Actions (`.github/workflows/norddesk.yml`) при изменениях
в `norddesk/`. Готовые файлы — в артефакте `norddesk` и в предвыпуске
`norddesk-latest`.

Локально (нужен только Go 1.24, зависимостей нет):

```bash
cd norddesk
# релей под Linux
GOOS=linux  GOARCH=amd64 CGO_ENABLED=0 go build -o norddesk-relay    ./cmd/relay
# хост и клиент под Windows
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o NordDesk-Host.exe ./cmd/host
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o NordDesk.exe      ./cmd/viewer
```

## Запуск

**1. Релей на VPS** (пример systemd-юнита):

```bash
sudo tee /etc/systemd/system/norddesk-relay.service >/dev/null <<'EOF'
[Unit]
Description=NordDesk relay
After=network.target
[Service]
ExecStart=/usr/local/bin/norddesk-relay -addr :8765
Restart=always
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now norddesk-relay
```

Релей держит только управляющие соединения; трафик зашифрован, но для обхода DPI
его можно поставить за TLS (nginx/caddy stream) или на 443.

**2. Хост** (на управляемом ПК):

```
NordDesk-Host.exe -relay ВАШ_VPS:8765
```

Покажет ID и код. Для своих машин без подтверждения: `-pw ПОСТОЯННЫЙ_ПАРОЛЬ`.

**3. Клиент** (на твоём ПК):

```
NordDesk.exe -relay ВАШ_VPS:8765
```

Откроется окно: введи ID и код хоста.

## Что уже работает (этап 1)

- Рандеву по ID через релей и сквозное шифрование.
- Трансляция экрана основного монитора (GDI, тайлы + JPEG, передаются только
  изменившиеся участки).
- Полное управление: мышь (включая колесо и правую кнопку), клавиатура.
- Перетаскивание файлов из окна прямо на рабочий стол хоста.
- Отправка буфера обмена хосту; регулировка качества/кадров на лету.
- Запрос согласия на стороне хоста; одноразовый код на подключение.

## Дорожная карта — что ещё пригодится IT-специалисту

Отсортировано по практической пользе:

- **Системный агент (служба) на хосте:** Ctrl+Alt+Del и работа на экране входа/UAC
  (сейчас их нельзя синтезировать из обычного процесса), автозапуск, доступ до входа
  пользователя. По аналогии со службой «NordKey VPN».
- **Файловый менеджер** в обе стороны: не только класть на рабочий стол, но и
  просматривать/забирать файлы с хоста, докачка.
- **Адресная книга и неприсмотренный доступ:** список своих машин с постоянными
  ID, онлайн-статус, подключение в один клик.
- **P2P через ICE/hole-punching** с релеем только как запасным каналом — ниже
  задержка и нагрузка на VPS (сейчас весь трафик идёт через релей).
- **Производительность:** захват через DXGI Desktop Duplication (события
  изменений вместо опроса) и кодек H.264/аппаратное кодирование вместо JPEG —
  плавнее и меньше трафик.
- **Несколько мониторов** и переключение между ними, масштабирование HiDPI.
- **Безопасность хоста во время сеанса:** затемнение экрана хоста, блокировка
  его клавиатуры/мыши, режим «только просмотр», чёрный список времени доступа.
- **Учётные записи и аудит:** вход для сотрудников, журнал подключений (кто/когда/
  откуда), двухфакторка, разрешения по ролям (как в NordKey).
- **Запись сессии** (видео) для разборов и отчётности.
- **Чат и голос** внутри сессии, передача текста/ссылок клиенту.
- **Перезагрузка с автоподключением**, Wake-on-LAN для спящих машин.
- **Буфер обмена с изображениями и файлами**, не только текст.
- **Удобство развёртывания:** MSI-установщик, подпись кода (убрать предупреждение
  SmartScreen, как отмечено в README NordKey), автообновление.
- **Кроссплатформенные хосты:** Linux (X11/PipeWire) и macOS.
- **Удалённая печать**, проброс звука.

## Ограничения этапа 1 (честно)

- Хост — только Windows x64; захват и ввод проверяются на реальной машине (в CI их
  не запустить — нет интерактивного рабочего стола).
- Один монитор; Ctrl+Alt+Del требует системного агента (см. дорожную карту).
- Весь трафик идёт через релей (P2P — следующий этап).
- Файлы пока не подписаны — SmartScreen предупредит при первом запуске.
